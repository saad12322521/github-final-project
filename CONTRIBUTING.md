# Contributing

Thank you for your interest in contributing to this project! All
contributions, bug reports, bug fixes, documentation improvements,
enhancements, and ideas are welcome.

## How to Contribute

### Reporting Bugs

If you find a bug, please open an issue on GitHub and include:

- A clear and descriptive title
- Steps to reproduce the problem
- Expected behavior vs. actual behavior
- Screenshots, if applicable
- Your environment details (browser, OS, etc.)

### Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues as well. When creating
an enhancement suggestion, please include:

- A clear and descriptive title
- A detailed description of the proposed enhancement
- An explanation of why this enhancement would be useful

### Submitting Changes (Bug Fixes / Documentation / Enhancements)

1. Fork the repository.
2. Create a new branch for your change:
   ```
   git checkout -b my-feature-branch
   ```
3. Make your changes, following the existing code style where possible.
4. Commit your changes with a clear commit message:
   ```
   git commit -m "Add: short description of the change"
   ```
5. Push the branch to your fork:
   ```
   git push origin my-feature-branch
   ```
6. Open a pull request against the `main` branch, describing what you
   changed and why.

### Documentation Improvements

Typos, clarifications, and additional examples in the README or other
documentation are always welcome — feel free to open a pull request
directly for these.

### Sharing Ideas

If you have an idea but aren't sure how to implement it, feel free to open
an issue to discuss it before writing any code.

## Code of Conduct

By participating in this project, you agree to abide by the rules laid out
in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Questions?

If you have any questions about contributing, feel free to open an issue
and ask.

Thank you for helping improve this project!
